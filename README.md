# Возврат ушедших клиентов падел-клуба

[![tests](https://github.com/danill3gacy/padel-return/actions/workflows/ci.yml/badge.svg)](https://github.com/danill3gacy/padel-return/actions/workflows/ci.yml)
[![Python 3.11+](https://img.shields.io/badge/python-3.11%2B-blue)](https://www.python.org/)
[![License: MIT](https://img.shields.io/badge/license-MIT-green)](LICENSE)
[![dependencies: none](https://img.shields.io/badge/dependencies-none-success)](requirements.txt)

Продукт берёт выгрузку клиентской базы клуба, находит тех, кто перестал ходить,
определяет вероятную причину ухода по истории броней и возвращает их персональным
предложением — **не скидкой, а конкретной игрой**: слот в привычное время с партнёрами
подходящего уровня. Клуб платит процент от выручки вернувшихся.

Работает **без единой зависимости**: только стандартная библиотека Python 3.11+ и SQLite.
LLM подключается по желанию — без ключа продукт работает на правилах и шаблонах.

## Задача

База клуба вымывается молча. В отчётах есть выручка и загрузка кортов, но нет
строки «перестали ходить»: ушедший клиент просто отсутствует в статистике.
Ручной обзвон не масштабируется, рассылка со скидкой бьёт по всем одинаково и
обесценивает абонемент. При этом реальное возражение чаще всего не цена, а
«не с кем играть и лень собирать четвёрку».

## Решение

Импорт выгрузки → поиск уснувших → гипотеза причины → персональный оффер →
кампания в мессенджерах → разбор ответов → отчёт клубу с честным uplift.
Клуб платит процент от выручки вернувшихся.

| Этап | Модуль | Суть |
|---|---|---|
| Импорт | `importer.py` | CSV из любой CRM: автоугадывание колонок, сохранённый маппинг |
| Признаки | `features.py` | Граф партнёрств восстанавливается по совпадению корта и времени |
| Сегментация | `segmentation.py` | «Спящий» = нарушение личного ритма, а не фиксированные 60 дней |
| Причина | `reasons.py` | Гипотеза ухода из закрытого списка |
| Оффер | `offers.py` | Сборка четвёрок, «уже двое, нужен третий» |
| Кампания | `campaign.py` | Три касания, тихие часы, очередь подтверждений |
| Ответы | `inbox.py` | Классификация, диалог, эскалация администратору |
| Деньги | `attribution.py` | Возвраты, выручка, uplift над контролем |

## Инженерные решения

- **Личный ритм вместо порога.** `days_since_last > max(45, avg_interval * 3)`:
  еженедельный игрок, пропавший на месяц, ушёл; ежемесячный — ещё нет.
  Фиксированный порог смешивает их и портит конверсию.
- **Оффер, а не скидка.** Иерархия жёсткая: собранная игра → игра, которая
  собирается → привычный слот → турнир → новичковая сессия → и только в конце цена.
- **Предложение усиливается по ходу кампании.** Согласившиеся копятся в пуле, и
  следующий адресат получает уже не «свободен корт», а «уже двое вашего уровня».
- **Human-in-the-loop.** Агент ведёт переписку, но бронь не пишет — ставит задачу
  администратору с кнопкой «Подтвердить».
- **Контрольная группа как основа расчётов.** Клуб платит за прирост над
  «оно бы и так вернулось», а не за все возвраты подряд.

## Стек

Стандартная библиотека Python 3.11+ и SQLite. Каналы: WhatsApp (Wazzup / Radist /
i-Digital), SMS, Telegram, консоль — за одним интерфейсом. Админка — Telegram-бот,
веба нет намеренно. LLM опционален: без ключа работают правила и шаблоны.

## Настройка

Всё через переменные окружения, ничего не хардкодится.

```bash
# LLM (необязательно — без него работают правила и шаблоны)
export PADEL_LLM_PROVIDER=anthropic          # none | anthropic | openai
export ANTHROPIC_API_KEY=sk-...
export PADEL_LLM_MODEL=claude-sonnet-4-5

# WhatsApp через российского провайдера (Wazzup, Radist, i-Digital)
export PADEL_CHANNEL=whatsapp
export PADEL_WA_URL=https://api.wazzup24.com/v3/message
export PADEL_WA_KEY=...
export PADEL_WA_CHANNEL=...

# Telegram: админ-бот и бесплатный канал для тех, кто уже подписан
export PADEL_TG_TOKEN=...

# Прогон без реальных отправок, но с подсчётом стоимости
export PADEL_DRY_RUN=1
```

Параметры сегментации, каденции и окон атрибуции — в `padelreturn/config.py`.
Настройки конкретного клуба (корты, часы работы, цены, пик) — в `clubs.settings_json`,
задаются командой `init`.

## Важное про каналы

**В Telegram нельзя написать человеку по номеру телефона.** Бот пишет только тем, кто сам
нажал `/start`. Поэтому холодное касание идёт через **WhatsApp Business API с шаблонами**
(~5–9 ₽ за сообщение), а внутри первого же диалога человек переводится в Telegram-бот клуба,
где следующие касания бесплатны. `channels.pick()` выбирает Telegram автоматически, если у
контакта есть `tg_chat_id`.

Накопление базы в Telegram — главная долгосрочная метрика продукта: она обнуляет стоимость
касания в следующих кампаниях.

## Правовая рамка

Не юридическая консультация, но это первое, о чём спросит вменяемый владелец:

- **152-ФЗ**: клуб — оператор персональных данных, вы — обработчик по поручению.
  Нужно поручение в договоре, хостинг в РФ.
- **38-ФЗ ст. 18**: согласие на рассылки должно быть в оферте клуба, которую клиент принял
  при первой брони. Проверять до старта кампании.
- **Отправитель — клуб, не вы.** WhatsApp-аккаунт и Telegram-бот регистрируются на клуб.
- Отписка в каждом первом сообщении, исполняется мгновенно, стоп-лист общий для всех кампаний.

Продукт это поддерживает: поле `consent`, `stop_list`, футер с отпиской в первом касании,
исключение недавно контактировавших, идемпотентность отправки.

## Этапы (из PRD)

- **M0** — кампания на коленке: `--channel console`, отправка руками с телефона клуба. ✅
- **M1** — автоматическая отправка, каденция, очередь подтверждений. ✅
- **M2** — диалоговый агент, эскалации. ✅
- **M3** — оффер-движок, сборка четвёрок, перевод базы в Telegram. ✅ (базовая версия)

Что осознанно **не** сделано до пятого клуба: интеграции по API с CRM, веб-админка,
мультиязычность, биллинг внутри продукта, аналитика сложнее одного отчёта.
